A signed-out visitor needs a way in. A signed-in person needs their name on the bar and a way out. This post wires a **NextAuth.js v5** session into **Gwan's `MenuBar`**, the horizontal app bar from the [SaaS dashboard walkthrough](/blog/saas-dashboard-weekend-build).

The file that renders the bar calls `useSession`, so that file needs `"use client"`.

## Install

Auth.js still publishes the Next.js v5 package on the `beta` tag. In a Next.js 16 App Router app:

```bash
npm install next-auth@beta gwan-design-system
npx auth secret
```

`AUTH_SECRET` is the env var Auth.js requires. A GitHub provider also reads `AUTH_GITHUB_ID` and `AUTH_GITHUB_SECRET`. These paths assume `@/*` maps to `./src/*`.

## Auth.js config

`auth.ts` is the single config. It exports `handlers`, `signIn`, `signOut`, and `auth`. The default session user has `name`, `email`, and `image`. A `role` is not included until you add it. The module augmentations below are the [TypeScript guide](https://authjs.dev/getting-started/typescript) pattern, and the callbacks are the [role-based access](https://authjs.dev/guides/role-based-access-control) pattern: copy `user.role` onto the JWT at sign-in, then copy `token.role` onto the session the client can read.

```ts
// src/auth.ts
import NextAuth, { type DefaultSession } from "next-auth";
import GitHub from "next-auth/providers/github";
// next-auth/jwt re-exports @auth/core. The import lets this augmentation resolve.
import type { JWT } from "next-auth/jwt";

declare module "next-auth" {
  interface Session {
    user: {
      role?: "admin" | "member";
    } & DefaultSession["user"];
  }

  interface User {
    role?: "admin" | "member";
  }
}

declare module "next-auth/jwt" {
  interface JWT {
    role?: "admin" | "member";
  }
}

export const { handlers, signIn, signOut, auth } = NextAuth({
  providers: [GitHub],
  callbacks: {
    jwt({ token, user }): JWT {
      if (user?.role) token.role = user.role;
      return token;
    },
    session({ session, token }) {
      if (session.user) session.user.role = token.role;
      return session;
    },
  },
});
```

Set the role in the provider `profile` callback. Until you do, `role` stays unset and the Admin item below stays hidden.

Expose the route handlers:

```ts
// src/app/api/auth/[...nextauth]/route.ts
import { handlers } from "@/auth";

export const { GET, POST } = handlers;
```

## Session provider

`useSession` reads a React context. Wrap the tree in `SessionProvider` from a file that has `"use client"`. The root layout can render that provider.

```tsx
"use client";

// src/components/auth-provider.tsx
import type { ReactNode } from "react";
import { SessionProvider } from "next-auth/react";

export function AuthProvider({ children }: { children: ReactNode }) {
  return <SessionProvider>{children}</SessionProvider>;
}
```

```tsx
// src/app/layout.tsx
import type { ReactNode } from "react";
import { AuthProvider } from "@/components/auth-provider";

export default function RootLayout({ children }: { children: ReactNode }) {
  return (
    <html lang="en">
      <body>
        <AuthProvider>{children}</AuthProvider>
      </body>
    </html>
  );
}
```

## The menu bar

`MenuBar` takes `menuItems` of type `IMenuItem`. Each item needs `title`, `route`, `isActive`, and `isDivider`. `icon` and `onClick` are optional. A submenu is `hasChildren: true` plus `children`, and each child is `{ title, route, isActive }`. `logoShort` and `logoLong` are required image paths. The bar does not navigate on its own: it calls `onNavigate` with the item `route`.

The signed-in user is rendered with `MenuBar`'s built-in avatar. When `isAvatarVisible` is true, `avatarName`, `avatarEmail`, `avatarImage`, and `avatarType` are all required. `avatarType` is an `AVATAR_VARIANT` member. `IMAGE_WITH_FULL` shows the photo when `avatarImage` is non-empty, and the initials swatch when it is empty, with the name and email beside it. Pass the session strings through, using `""` when a field is missing, including a blank name so the swatch can fall back to the email.

Name and email come from those props, so this bar does not render `Ellipsis`. Where you do truncate a string yourself, `Ellipsis` takes `label`.

Sign in and Sign out go in `rightSlot` as `Button`, with `label` and `onClick`. While `useSession` reports `"loading"`, set `MenuBar`'s `isLoading` so the items are replaced by the built-in shimmer, and render no button yet.

The client `signIn()` and `signOut()` used here are the ones from `next-auth/react`. `signOut` takes `redirectTo`.

```tsx
"use client";

// src/components/app-menu-bar.tsx
import { usePathname, useRouter } from "next/navigation";
import { signIn, signOut, useSession } from "next-auth/react";
import {
  AVATAR_VARIANT,
  BUTTON_VARIANTS,
  Button,
  DashboardSVG,
  MenuBar,
  SettingsSVG,
  type IMenuItem,
} from "gwan-design-system";

export default function AppMenuBar() {
  const pathname = usePathname();
  const router = useRouter();
  const { data: session, status } = useSession();
  const user = session?.user;

  const menuItems: IMenuItem[] = [
    {
      title: "Dashboard",
      icon: <DashboardSVG />,
      route: "/dashboard",
      isActive: pathname.startsWith("/dashboard"),
      isDivider: false,
    },
    {
      title: "Projects",
      route: "/projects",
      isActive: pathname.startsWith("/projects"),
      isDivider: false,
    },
    {
      title: "Settings",
      icon: <SettingsSVG />,
      route: "/settings",
      isActive: pathname.startsWith("/settings"),
      isDivider: false,
    },
  ];

  if (user?.role === "admin") {
    menuItems.push({
      title: "Admin",
      route: "/admin",
      isActive: pathname.startsWith("/admin"),
      isDivider: false,
    });
  }

  const rightSlot =
    status === "authenticated" ? (
      <Button
        variant={BUTTON_VARIANTS.TERTIARY}
        label="Sign out"
        onClick={() => {
          void signOut({ redirectTo: "/" });
        }}
      />
    ) : status === "unauthenticated" ? (
      <Button
        variant={BUTTON_VARIANTS.SECONDARY}
        label="Sign in"
        onClick={() => {
          void signIn();
        }}
      />
    ) : null;

  const avatar = user
    ? {
        isAvatarVisible: true as const,
        avatarName: user.name ?? "",
        avatarEmail: user.email ?? "",
        avatarImage: user.image ?? "",
        avatarType: AVATAR_VARIANT.IMAGE_WITH_FULL,
      }
    : { isAvatarVisible: false as const };

  return (
    <MenuBar
      menuItems={menuItems}
      logoShort="/logo-mark.svg"
      logoLong="/logo.svg"
      sticky
      isLoading={status === "loading"}
      onNavigate={(route) => {
        if (route.length > 0) router.push(route);
      }}
      rightSlot={rightSlot}
      {...avatar}
    />
  );
}
```

## Protect routes with `proxy.ts`

Next.js 16 renamed `middleware.ts` to `proxy.ts` and the exported function to `proxy`. The file sits next to `app` (so `src/proxy.ts` when you use a `src` directory).

Auth.js wraps that function with `auth`. The installation guide's one-line form is `export { auth as proxy } from "@/auth"`, which keeps the session expiry fresh. The wrapper below is the same `auth()` with the redirect written out, matching the [protecting guide](https://authjs.dev/getting-started/session-management/protecting). The matcher lists only private sections, so the redirect target is not run through this check.

```ts
// src/proxy.ts
import { auth } from "@/auth";

export const proxy = auth((req) => {
  const pathname = req.nextUrl.pathname;
  const isProtected =
    pathname.startsWith("/dashboard") ||
    pathname.startsWith("/settings") ||
    pathname.startsWith("/admin");

  if (isProtected && !req.auth) {
    return Response.redirect(new URL("/api/auth/signin", req.nextUrl.origin));
  }
});

export const config = {
  matcher: ["/dashboard/:path*", "/settings/:path*", "/admin/:path*"],
};
```

Do not rely on the proxy as the only check. Read the session again beside the data you are protecting.

## What's new in this release

[PR #135](https://github.com/gwanfonseka/gwan-design-system/pull/135) is the release that shows up in this bar. No public props, exports, or TypeScript types changed. Two of the fixes are visible once a session is on screen. The behaviour below is only what that pull request, and the Avatar and MenuBar commits in it, state.

**Stable pastel.** The swatch was a new random pastel on every mount. It is now an FNV-1a hash of the name, or of the email when the name is blank, in the same 60–80% saturation and 75–85% lightness band, including on the server. [Commit `53ae217`](https://github.com/gwanfonseka/gwan-design-system/commit/53ae21744a464870da799b3f0dbef53f8eb1e929) describes the fix as: derive it from the name, falling back to the email, so server and client match. `MenuBar` passes `avatarName` and `avatarEmail` through to that avatar.

**Keyboard.** The keyboard behaviour follows the WAI-ARIA menubar pattern. Before this release there was no Arrow, Home, End, or Escape handling, no roving tabindex, and no focus wrap. Enter and Space only activated the focused button. Left and Right now move across the bar and wrap. Up and Down open a submenu and wrap inside it. Home and End move to the ends. Escape closes a submenu or More and returns focus. One item has `tabindex=0`. Enter and Space still activate. Arrow keys do not. Tab still leaves the bar. [Commit `19cb919`](https://github.com/gwanfonseka/gwan-design-system/commit/19cb9194cd2c319681b257e0979ba51e96443a80) puts the same change as: focus now moves with those keys, wraps at the ends, and Escape closes the open menu. Enter and Space still activate.

## Summary

Read the session with `useSession` inside a file that has `"use client"`. Pass `IMenuItem` entries (`title`, `route`, `isActive`, `isDivider`) and the required logos to `MenuBar`. Turn the built-in avatar on with `isAvatarVisible`, `avatarName`, `avatarEmail`, `avatarImage`, and `avatarType`. Put Sign in and Sign out in `rightSlot` as a `Button` with `label` and `onClick`. Set `isLoading` while the session status is `"loading"`. Gate the private routes in `proxy.ts` with the `auth()` wrapper.
